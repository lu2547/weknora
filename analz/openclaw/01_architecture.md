# OpenClaw 架构详解：五层运行时网关设计

## 一、架构设计理念

OpenClaw 不是一个简单的聊天机器人或工具调用框架，而是一个集成了消息处理、会话治理、上下文管理、技能执行和多 Agent 协作的**完整运行时网关系统（Agent Runtime）**。

其工程设计的核心价值在于：**将用户请求转化为一条可治理、可扩展、可追踪的执行链路**。

### 第1层：用户接口层

提供 CLI、Web UI、移动 App、WebSocket API 等入口，把用户操作转成统一的内部请求。

对用户来说，可能只是网页里输入一句话，或者在钉钉、飞书里发一条消息；但对系统来说，这些入口最终都要**收敛成统一的内部消息模型**。

### 第2层：Gateway核心层

这是 OpenClaw 的核心运行时，负责：

| 组件       | 职责                       |
| ---------- | -------------------------- |
| 连接管理   | 维护与各种渠道的长连接     |
| 请求接入   | 接收并预处理所有入站请求   |
| 配置热加载 | 支持运行时配置更新无需重启 |
| 健康监控   | 系统状态检查与告警         |

**真正让整个系统常驻运行、能接消息、能回消息、能维持状态的，不是单个 Agent，而是这个 Gateway。**

### 第3层：消息处理层

业务逻辑真正流转的核心：

| 组件        | 职责                      |
| ----------- | ------------------------- |
| Agent执行器 | 调用 LLM 进行推理和决策   |
| 路由系统    | 决定消息由哪个 Agent 处理 |
| 会话管理    | 维护对话状态和历史        |
| 媒体处理    | 图片、文件等多媒体处理    |
| 出站投递    | 将响应发送回用户          |
| 上下文组装  | 为 LLM 组装完整上下文     |
| 记忆召回    | 检索相关历史记忆          |

### 第4层：扩展与插件层

所有可插拔的扩展：

- **通道插件**：对接钉钉/飞书、Telegram、WhatsApp、Slack 等 50+ 平台
- **技能工具系统**：模块化能力扩展
- **Sub Agent机制**：多 Agent 协作支持

### 第5层：基础设施层

通用能力支撑：

- 配置与密钥管理
- 结构化日志
- 定时任务
- 事件总线
- 记忆检索
- 沙箱安全

## 三、中心辐射式架构

OpenClaw 采用中心辐射式架构（Hub-and-Spoke），以 Gateway 网关为核心中枢：

```
                    ┌─────────────────┐
                    │    Gateway      │
                    │   (Port 18789)  │
                    └────────┬────────┘
                             │
           ┌─────────────────┼─────────────────┐
           │                 │                 │
           v                 v                 v
    ┌─────────────┐   ┌─────────────┐   ┌─────────────┐
    │   Node 1    │   │   Node 2    │   │   Node 3    │
    │  (本地设备)  │   │  (服务器)   │   │  (云主机)   │
    └─────────────┘   └─────────────┘   └─────────────┘
```

### 网关层

- 系统的"指挥中枢"
- 负责多渠道集成、路由规则管理和状态同步
- 默认占用 18789 端口进行 WebSocket 通信

### 节点层

- 真正"干活"的进程
- 安装在需要操作的具体设备上
- 能够获取宿主系统的文件系统、进程列表及 GUI 视觉信息
- 支持通过 Docker 或 Sandbox 运行不信任的代码

## 四、消息执行完整链路

### 链路概览

```
消息源 → 协议适配 → 路由分发 → 会话构建 → Agent执行 → 响应投递 → 状态持久化
```

### 详细流程

#### Step 1：消息进门

用户在钉钉发送消息：
```
帮我整理今天的重要邮件，提炼待办并生成一份给老板的简报
```

从系统视角看，钉钉的消息格式和飞书不一样，Discord 和 WhatsApp 不一样，需要做**协议适配**。

#### Step 2：协议适配

每个外部渠道都有一个专属适配器插件，把原始消息清洗成统一的内部对象 `MsgContext`：

```typescript
interface MsgContext {
    Body: string;              // 消息正文
    BodyForAgent?: string;     // 给Agent看的正文
    BodyForCommands?: string;  // 命令解析用正文
    SessionKey: string;        // 会话标识
    Provider: string;          // 来源平台
    ChatType?: "direct" | "group";  // 聊天类型
    SenderId?: string;         // 发送者ID
    SenderName?: string;       // 发送者名称
    // ...
}
```

**平台差异被隔离在网关入口，不污染整个 Agent 执行链路。**

#### Step 3：统一关卡

所有封装好的 `MsgContext` 流入统一入口 `dispatchInboundMessage`：

1. **去重**：基于 `idempotencyKey`，默认 TTL 20 分钟
2. **拦截**：控制命令处理
3. **路由**：决定由哪个 Agent 处理

#### Step 4：路由分发

路由系统根据通道类型决定消息由哪个 Agent 处理：

- **Web内部通道**：可直接指定 `sessionKey`（格式如 `{agentId}:{scope}`）
- **外部通道**：依赖绑定规则匹配

#### Step 5：会话隔离

系统通过"会话车道"机制保证：
- 同一 `sessionKey` 下的消息串行执行
- 防止上下文错乱
- 结合全局并发控制进行资源治理

#### Step 6：上下文组装

Agent 执行前，系统为模型组装分层上下文：

```
系统提示词（Bootstrap文件系统注入）
    ↓
技能提示（Skills描述注入）
    ↓
对话历史（sessions.json + JSONL）
    ↓
当前消息
```

#### Step 7：Agent执行

采用 ReAct 范式执行，流式处理工具调用和错误回退。

#### Step 8：响应投递

任务完成后：
1. 响应投递回用户
2. 会话持久化
3. 资源清理

## 五、新增渠道扩展

如果需要接一个新通道，只需四步：

```
1. 在 Registry 中添加通道元数据
2. 实现对应的 ChannelPlugin
3. 在插件加载器里注册新插件
4. 更新配置 Schema 和文档测试
```

整个过程**无需改核心系统代码**，这就是插件化设计真正有价值的地方。

## 六、工作流引擎

### 节点类型

OpenClaw 的工作流引擎由多种节点组成：

| 节点类型  | 功能                   |
| --------- | ---------------------- |
| Start     | 流程入口，接收用户输入 |
| LLM       | 调用大模型生成回复     |
| Tool      | 执行工具函数           |
| Condition | 条件分支               |
| Loop      | 循环执行               |
| End       | 流程结束               |

### 模型调度器

抽象了统一的模型接口：
- 屏蔽不同厂商的差异
- 支持多模型切换
- 负载均衡
- 重试容错机制

## 八、与传统 Agent 框架对比

| 维度       | AutoGPT（2023）  | OpenClaw（2025）               |
| ---------- | ---------------- | ------------------------------ |
| 任务持久化 | 内存中，重启丢失 | 工作区文件系统 + 心跳          |
| 能力扩展   | Python 插件      | SKILL.md（Markdown Prompt）    |
| 多渠道     | 仅 Web UI        | QQ/飞书/Telegram/WhatsApp 等   |
| 社区生态   | 碎片化           | ClawHub 25,000+ 技能           |
| 模型兼容   | 绑定 OpenAI      | 任意 OpenAI/Anthropic 兼容模型 |

OpenClaw 的真正突破在于**把 Agent 从"技术 Demo"变成了"日常工具"**。
